# Рецепт

## Problem

Ситуация, которую решает рецепт, в двух-трёх предложениях. Называйте симптом, а не тему.

## When to use

Конкретные предпосылки. Если предпосылку нельзя проверить чтением файла или командой — это не
предпосылка.

## When not to use

Соседние случаи, где рецепт неверен. Этот раздел предотвращает большинство плохого переиспользования.

## Prerequisites

Инструменты, версии, права, доступ. Номера версий — часть рецепта.

## Inputs

Что оператор обязан предоставить: путь, имя таблицы, целевое окружение.

## Procedure

1. Одно действие на шаг.
2. Каждый шаг называет ожидаемое наблюдение.
3. Ни один шаг не зависит от прошлой переписки.

## Commands or code

```text
# Только очищенный пример. Для хостов, путей и идентификаторов — <PLACEHOLDER>.
```

## Expected result

Что видит оператор, когда получилось, — достаточно точно, чтобы отличить успех от почти-успеха.

## Validation

Чем результат доказан, командой или наблюдением. «Выглядело правильно» — не проверка.

## Rollback

Как отменить, по шагам. Если отката нет — сказать это и сказать, что делает действие безопасным.

## Known failures

Каждый известный провал с симптомом и рабочим обходом. Ссылка на запись `failure` по id.
