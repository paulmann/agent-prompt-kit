# agent-prompt-kit

**На других языках:** [English](README.md) · [Deutsch](README.de.md) · [中文](README.zh.md) · [हिन्दी](README.hi.md) · [Español](README.es.md) · Русский

**Превращает уже сделанную работу в специализированное окружение для следующей. Одна команда читает текущую сессию и связанные сессии рантайма, пишет карточку задачи и карточку домена и создаёт рабочее пространство или сохранённого агента, в котором уже лежат правила, критерий приёмки, разобранные примеры и хранилище прежней работы. Четырнадцать модулей, проверяемых машиной.**

Хороший ответ умирает вместе с чатом. Когда тот же класс работ приходит снова, свежая сессия
начинает с нуля: тот же разбор, те же тупики, те же вопросы. Этот набор делает такое повторение
дешёвым — не тем, что агент «лучше помнит», а тем, что после работы остаётся
**зарегистрированное рабочее окружение**.

Одна команда — один результат: каталог (рабочее пространство или сохранённый агент), в котором
уже лежат правила для этого класса работ, карточка домена с проверяемым критерием приёмки,
разобранные примеры, включая один провал, хранилище прежней работы и стартовый промпт для
следующего окна.

| Что делает команда | Почему это важно |
|---|---|
| читает текущую сессию **и связанные сессии рантайма** | материал — настоящая работа, а не её описание |
| пишет карточку задачи и карточку домена до начала действий | тема объявлена, а не подразумевается |
| создаёт каталог окружения, где каждая часть на месте | следующий круг начинается с одиннадцатого шага, а не с первого |
| называет шаг регистрации, для каждого рантайма свой | HARNESS: один клик; AutoClaw2: перезагрузка; делать вид, что это не так, — и есть дефект |
| передаёт стартовый промпт | каталог без передачи — музей, а не рабочее место |

Каждое утверждение о рантайме в этом репозитории помечено: замерено здесь или сообщено из сессии —
см. [`docs/INSTALL.md`](docs/INSTALL.md).

## Что это

Один файл `PROMPT.md` плюс материал, который нужен, чтобы ему доверять и его адаптировать.

| Часть | Что она даёт |
|---|---|
| [`PROMPT.md`](PROMPT.md) | сам системный промпт: 14 модулей, 14 самопроверок, 10 инвариантов |
| [`AGENTS.md`](AGENTS.md) | тот же контракт в машинной форме — для кодирующих агентов, которые читают правила репозитория |
| [`skills/experience-reuse/`](skills/experience-reuse/SKILL.md) | навык M13: рабочий процесс, чек-лист применимости, четыре шаблона записей, политика безопасности |
| [`tools/experience.py`](tools/experience.py) | хранилище опыта и его выборка одной командой, с проверкой схемы и секретов |
| [`memory/`](memory/README.md) | где лежат записи; три очищенных примера идут в поставке набора |
| [`tools/prompt_lint.py`](tools/prompt_lint.py) | проверяет полноту модулей, парность переводов, заготовки, ссылки, секреты, согласованность версий, M13 и ширину ворот |
| [`examples/EXAMPLES.md`](examples/EXAMPLES.md) | три домена одной формы: обычный случай, неоднозначный случай, случай провала |
| [`docs/`](docs/) | обоснование дизайна, протокол адаптации, чек-лист QA, валидация по исходной цели |

Промпт решает пять конкретных проблем, в таком порядке:

1. **Дрейф темы** — агент отвечает на соседний, более лёгкий вопрос. Противоядие — карточка задачи
   (M1) и карточка домена (M2), которые обязаны существовать до любого действия.
2. **Выдуманный контекст** — «как мы обсуждали раньше» про переписку, которую никто не читал.
   Противоядие — журнал контекста (M3) и три метки свидетельств (M4).
3. **Непроверяемые утверждения** — «это работает» без наблюдения. Противоядие — рабочий цикл (M5),
   таблица возможностей (M6) и ворота (M8).
4. **Повторная работа** — задача решается заново, потому что прежняя попытка нигде не всплыла.
   Противоядие — хранилище опыта и проверка применимости (M13).
5. **Стоимость переиспользования** — новый домен означает переписать промпт. Противоядие — протокол
   специализации (M10): одна карточка, один файл примеров, одна строка приёмки.

## Установка

```bash
git clone https://github.com/paulmann/agent-prompt-kit.git
cd agent-prompt-kit

python tools/prompt_lint.py            # exit 0 means the document is structurally complete
```

Нужен только Python 3.11+. Ни пакетов, ни сервиса, ни учётной записи.

## Рантаймы

Одна и та же процедура, три разных механизма. Что может модель и что обязан человек — в каждом
рантайме по-своему, и таблица говорит, что именно. Замерено на этой машине либо помечено как
сообщённое из сессии.

| Рантайм | Команда | Модель делает | Человек делает | Проверено |
|---|---|---|---|---|
| **AutoClaw2** | `/agent-prompt-kit` (а также `/skill:agent-prompt-kit`) | пишет навык в `%USERPROFILE%\.pi\agent\skills\` и команду в `...\prompts\` | перезагружает приложение, чтобы снимок ресурсов пересобрался | замерено в бандле приложения |
| **HARNESS** | `/agent-prompt-kit` | создаёт весь каталог рабочего пространства со всеми файлами | один клик: добавить каталог как рабочее пространство | механизм замерен здесь; клик — со слов из сессии |
| **SagaAI** | — | вставляет `PROMPT.md` как рабочий контракт | так, как требует рантайм | **не проверено**: установщик отказывается угадывать |

```bash
python tools/install.py --runtime autoclaw2 --check    # files plus registration state
python tools/install.py --runtime autoClaw2 --write    # install, backup anything it replaces
python tools/install.py --runtime harness  --write
```

Установщик никогда не сообщает ручной шаг как выполненный. В HARNESS он печатает клик; в AutoClaw2
сверяет манифест ресурсов и говорит `NOT READY`, пока перезагрузка не произошла. Полная механика и
таблица ловушек: [`docs/INSTALL.md`](docs/INSTALL.md).

## Использование

1. Откройте `PROMPT.md`.
2. Вставьте всё, что ниже заголовка YAML, в поле системного промпта вашего агента.
3. Дайте агенту настоящий запрос. Он обязан ответить карточкой задачи, карточкой домена,
   результатом, метками свидетельств и строкой ворот.

Промпт сознательно не привязан к инструментам — см. [Переносимость](#переносимость). Разобранный
ответ в трёх несвязанных доменах лежит в [`examples/EXAMPLES.md`](examples/EXAMPLES.md).

## Четырнадцать модулей

| Модуль | На какой вопрос отвечает | Чем проверяется |
|---|---|---|
| M0 | Чей это голос и в каких двух фазах он работает? | тема названа одним предложением |
| M1 | Что на самом деле просят? | карточка задачи, каждое поле заполнено или `unknown` |
| M2 | Какой специалист нужен и что должно быть проверено? | карточка домена, условие приёмки проверяемо |
| M3 | Какой контекст есть и насколько он хорош? | журнал контекста с источником на каждое утверждение |
| M4 | Как помечать то, что я знаю? | `[fact]` / `[inference]` / `[assumption]` |
| M5 | Как работать, ничего не ломая? | цикл: рамка → выборка → план → действие → проверка → запись |
| M6 | Чем можно пользоваться и что запрещено? | таблица возможностей, правила безопасности |
| M7 | Какую форму имеет ответ? | пять разделов плюс необязательный раздел переиспользованного опыта |
| M8 | Откуда знать, что работа закончена? | двенадцать проверок, сообщаемых одной строкой |
| M9 | Как этот промпт можно сломать? | шестнадцать режимов отказа с противоядиями |
| M10 | Как направить его на новый домен? | одна карточка, один файл примеров, одна строка приёмки |
| M11 | Как выглядит хороший ответ? | три разобранных примера |
| M12 | Что проверяют перед отправкой? | пять вопросов, по одной строке ответа на каждый |
| M13 | Как не делать заново уже сделанное? | выборка до планирования, вердикт применимости, очищенное хранилище |

## Переиспользование опыта

M13 превращает «мы это уже делали» из надежды в вызов инструмента:

```bash
python tools/experience.py search "add nullable column to list endpoint" --limit 5
```

```text
query: add nullable column to list endpoint  ·  2 candidate(s)
  [ 25] recipe    add-nullable-column-to-list-endpoint validated overlap 5, validated, high confidence, verified 2d ago
  [ 11] failure   retry-migration-until-it-passes    validated overlap 1, validated, prior failure: read before acting
```

Каждая строка несёт причину своей позиции, поэтому агент отвергает кандидата по свидетельству, а не
по ощущению. Переиспользование решают шесть вопросов — цель, окружение, допущения, покрытие
проверкой, безопасность, свежесть, — и невысказанная адаптация считается слепым копированием.

Что хранилище отвергает, по своим же тестам: запись с литералом, похожим на токен, рецепт без
раздела `Rollback`, запись без `last_verified_at`, помеченную `validated`. О чём предупреждает:
о проверке старше 180 дней, о почти совпадающем заголовке. Чего не делает никогда: не удаляет —
записи помечаются устаревшими со ссылкой на замену.

## Ворота качества

Агент обязан напечатать одну строку, например `gate 12/12` или `gate 10/12 — 6, 9 failed: <reason>`.
Двенадцать проверок определены в M8; две, которые на практике проваливаются чаще всего:

- **№4 покрытие свидетельствами** — фактическое утверждение, так и не попавшее в журнал контекста;
- **№6 проверка** — «это работает» без команды или наблюдения.

Строка ворот — не украшение: именно она делает ответ аудируемым для того, кто не видел, как работал
агент. `docs/QA.md` превращает те же двенадцать проверок в человеческий чек-лист ревью.

## Переносимость

В промпте нет имён инструментов. Возможности названы классом и разрешаются в каждом рантайме:

| Класс возможности | Примеры соответствий |
|---|---|
| `read-files` | инструмент чтения, `cat` в оболочке, буфер редактора |
| `write-files` | инструмент записи или патча, heredoc, встроенная подсказка |
| `run-commands` | оболочка, песочница, CI-раннер |
| `web-search` | инструмент поиска, браузер, адреса, присланные пользователем |
| `publish` | `git push`, реестр пакетов, API вики |

Если в рантайме возможности нет, промпт деградирует явно (M6): просит содержимое, выдаёт артефакт
текстом или называет отсутствующую возможность. Он никогда не притворяется.

Проверенные цели импорта: AutoClaw2, HARNESS, SagaAI и любой агент, принимающий системный промпт.
Машинный вариант — [`AGENTS.md`](AGENTS.md).

## Разработка

```bash
python tools/prompt_lint.py            # structural contracts
python tools/prompt_lint.py --json     # machine-readable findings
```

Правка промпта:

1. Правьте `PROMPT.md`; идентификаторы модулей не меняйте — на них ссылаются инструменты и ревью.
2. Обновите `PROMPT.ru.md` тем же коммитом.
3. Поднимите `version` в заголовке файла и добавьте запись в `CHANGELOG.md`; линтер сравнивает их.
4. Гоняйте линтер, пока он не выйдет с кодом `0`.
