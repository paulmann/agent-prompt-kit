# agent-prompt-kit

**Переносимый системный промпт, превращающий любого ИИ-агента в специалиста по теме во время работы: он выводит тему и набор навыков из переписки, достаёт прежнюю работу вместо её повторения, помечает каждое утверждение и проверяет собственный вывод воротами качества. Четырнадцать нумерованных модулей, проверяемых машиной.**

Промпты агентов проваливаются двумя способами: они либо настолько общие, что агент отвечает
поверхностно обо всём, либо настолько привязаны к домену, что их нельзя переиспользовать. Этот
набор идёт третьим путём: агент универсален, пока не прочитал запрос, — затем он выписывает тему,
набор навыков, факты, которые обязан проверить, и собственное определение готовности, и работает
внутри этого контракта.

Вторая статья расходов — повторение: та же миграция, релиз или проход по документации делается
заново, потому что ничто не напоминает агенту, что это уже было. M13 закрывает это хранилищем
прежней работы и одной командой доставания: повторная задача стоит один поиск, а не повторный
разбор.

> `python tools/prompt_lint.py`. Длинные руководства — в [`docs/`](docs/) и

## Что это

Один файл `PROMPT.md` плюс материал, чтобы ему доверять и его адаптировать.

| Часть | Что даёт |
|---|---|
| [`PROMPT.ru.md`](PROMPT.ru.md) | сам промпт: 14 модулей, 14 самопроверок, 9 инвариантов |
| [`AGENTS.ru.md`](AGENTS.ru.md) | тот же контракт в машинной форме — для агентов, читающих правила репозитория |
| [`skills/experience-reuse/`](skills/experience-reuse/SKILL.ru.md) | навык M13: workflow, чек-лист применимости, четыре шаблона записей, политика безопасности |
| [`tools/experience.py`](tools/experience.py) | хранилище опыта и доставание одной командой, с проверкой схемы и секретов |
| [`memory/`](memory/README.ru.md) | где живут записи; три очищенных примера идут в поставке |
| [`tools/prompt_lint.py`](tools/prompt_lint.py) | проверяет полноту модулей, парность переводов, заготовки, ссылки, секреты, согласие версий, M13 и ширину ворот |
| [`examples/EXAMPLES.ru.md`](examples/EXAMPLES.ru.md) | три домена одной формы: обычный случай, неоднозначный, провал |
| [`docs/`](docs/) | обоснование дизайна, протокол адаптации, чек-лист QA, валидация по исходной цели |

Промпт решает пять конкретных проблем, по порядку:

1. **Дрейф темы** — агент отвечает на соседний, более лёгкий вопрос. Противоядие — карточка задачи
   (M1) и карточка домена (M2), существующие до любого действия.
2. **Выдуманный контекст** — «как мы обсуждали» о переписке, которую не читали. Противоядие —
   журнал контекста (M3) и три метки свидетельств (M4).
3. **Непроверяемые утверждения** — «это работает» без наблюдения. Противоядие — рабочий цикл (M5),
   таблица возможностей (M6) и ворота (M8).
4. **Повторная работа** — та же задача делается заново, потому что прежняя попытка не всплыла.
   Противоядие — хранилище опыта и проверка применимости (M13).
5. **Стоимость переиспользования** — новый домен требует переписать промпт. Противоядие — протокол
   специализации (M10): одна карточка, один файл примеров, одна строка приёмки.

## Установка

```bash
git clone https://github.com/paulmann/agent-prompt-kit.git
cd agent-prompt-kit

python tools/prompt_lint.py            # код 0 — документ структурно полон
```

Нужен только Python 3.11+. Ни пакетов, ни сервиса, ни учётной записи.

## Использование

1. Откройте `PROMPT.ru.md`.
2. Вставьте всё ниже YAML-заголовка в поле системного промпта вашего агента.
3. Дайте агенту настоящий запрос. Он обязан ответить карточкой задачи, карточкой домена,
   результатом, метками свидетельств и строкой ворот.

Промпт сознательно не привязан к инструментам — см. [Переносимость](#переносимость). Проработанный
ответ в трёх несвязанных доменах — в [`examples/EXAMPLES.ru.md`](examples/EXAMPLES.ru.md).

## Четырнадцать модулей

| Модуль | На какой вопрос отвечает | Чем проверяется |
|---|---|---|
| M0 | Чей это голос и какие у него две фазы? | тема названа одним предложением |
| M1 | Что на самом деле просят? | карточка задачи, каждое поле заполнено или `неизвестно` |
| M2 | Какой специалист нужен и что он обязан проверить? | карточка домена, условие приёмки проверяемо |
| M3 | Какой контекст существует и насколько он хорош? | журнал контекста с источником на утверждение |
| M4 | Как помечать то, что я знаю? | `[факт]` / `[вывод]` / `[предположение]` |
| M5 | Как работать, ничего не ломая? | цикл: рамка → достать → план → шаг → проверка → запись |
| M6 | Чем можно пользоваться и что запрещено? | таблица возможностей, правила безопасности |
| M7 | Какую форму имеет ответ? | пять разделов плюс необязательный раздел использованного опыта |
| M8 | Откуда знать, что работа закончена? | одиннадцать проверок, сообщаемых строкой |
| M9 | Как побеждают этот промпт? | шестнадцать режимов отказа с противоядиями |
| M10 | Как направить его на новый домен? | одна карточка, один файл примеров, одна строка приёмки |
| M11 | Как выглядит хороший ответ? | три проработанных примера |
| M12 | Что проверить перед отправкой? | пять вопросов, по строке на каждый |
| M13 | Как не делать заново уже сделанное? | доставание до планирования, вердикт применимости, очищенное хранилище |

## Переиспользование опыта

M13 превращает «мы это делали» из надежды в вызов инструмента:

```bash
python tools/experience.py search "добавить nullable колонку в эндпоинт списка" --limit 5
```

```text
query: добавить nullable колонку в эндпоинт списка  ·  2 candidate(s)
  [ 25] recipe    add-nullable-column-to-list-endpoint validated overlap 5, validated, high confidence, verified 2d ago
  [ 11] failure   retry-migration-until-it-passes    validated overlap 1, validated, prior failure: read before acting
```

Каждая строка несёт причину своей позиции, поэтому агент отвергает кандидата по свидетельству, а не
по ощущению. Переиспользование решают шесть вопросов — цель, окружение, допущения, покрытие
проверкой, безопасность, свежесть, — и невысказанная адаптация считается слепым копированием.

Что хранилище отвергает, по своим же тестам: запись с литералом, похожим на токен; рецепт без
раздела `Rollback`; запись без `last_verified_at`, помеченную `validated`. О чём предупреждает:
проверка старше 180 дней, почти-дубликат заголовка. Чего не делает никогда: не удаляет — записи
помечаются устаревшими со ссылкой на замену.

## Ворота качества

Агент обязан напечатать одну строку, например `ворота 11/11` или
`ворота 9/11 — 6, 9 провалены: <причина>`. Одиннадцать проверок определены в M8; две, что
проваливаются чаще всего на практике:

- **№4 покрытие свидетельствами** — фактическое утверждение, не попавшее в журнал контекста;
- **№6 проверка** — «это работает» без команды или наблюдения.

Строка ворот — не украшение: именно она делает ответ аудируемым для того, кто не видел работы
агента. `docs/QA.md` превращает те же одиннадцать проверок в человеческий чек-лист ревью.

## Переносимость

В промпте нет имён инструментов. Возможности названы классом и разрешаются в каждом рантайме:

| Класс возможности | Примеры соответствий |
|---|---|
| `read-files` | инструмент чтения, `cat` в оболочке, буфер редактора |
| `write-files` | инструмент записи/патча, heredoc, встроенная подсказка |
| `run-commands` | оболочка, песочница, CI-раннер |
| `web-search` | поиск, браузер, присланные пользователем адреса |
| `publish` | `git push`, реестр пакетов, API вики |

Если возможности нет, промпт деградирует явно (M6): просит содержимое, выдаёт артефакт текстом или
называет отсутствующую возможность. Он никогда не делает вид.

Проверенные цели импорта: AutoClaw2, HARNESS, SagaAI и любой агент, принимающий системный промпт.
Машинный вариант — [`AGENTS.ru.md`](AGENTS.ru.md).

## Разработка

```bash
python tools/prompt_lint.py            # структурные контракты
python tools/prompt_lint.py --json     # машинный вывод
```

Правка промпта:

1. Правьте `PROMPT.md`; идентификаторы модулей не меняйте — на них ссылаются инструменты и ревью.
2. Обновите `PROMPT.ru.md` тем же коммитом.
3. Поднимите `version` в заголовке и добавьте запись в `CHANGELOG.md`; линтер сравнивает их.
4. Гоняйте линтер до кода `0`.
