# memory/ — хранилище опыта

Здесь лежит прежняя работа: один Markdown-файл на запись, проверяемый по схеме и доставаемый одной
командой. Навык, который им управляет, — `skills/experience-reuse/SKILL.ru.md`; модуль в промпте — M13.

```bash
python tools/experience.py check                                      # хранилище в порядке?
python tools/experience.py search "добавить nullable колонку в эндпоинт"  # достать до планирования
python tools/experience.py add skills/experience-reuse/examples/recipe.md
python tools/experience.py stats
```

Четыре каталога, по одному типу записи в каждом: `recipes/`, `failures/`, `tasks/`, `artifacts/`.

## Что здесь уместно

Запись стоит делать, когда работу дороже десяти минут открыть заново, а результат переиспользуем:
процедура, которая применится снова; провал, который дорого дался; артефакт, который можно
адаптировать; задача, чей исход объясняет более позднюю.

Запись **не** уместна, когда она разовая, содержит приватный контекст или утверждает непроверенное.

## Чего здесь быть не должно

Учётных данных, персональных данных, содержимого заказчика, внутренних имён хостов и абсолютных
путей машины. В поставке только три очищенных примера — в них везде `<PLACEHOLDER>`, а
`experience.py check` падает на литерале, похожем на токен.

## Статус вместо удаления

`draft` → `validated` → `deprecated`. Устаревшая запись помечается со ссылкой на замену и никогда не
удаляется: след аудита — причина, по которой хранилищу прежней работы вообще можно доверять.
`last_verified_at` старше 180 дней даёт предупреждение; снимает его только реальный повторный прогон.
